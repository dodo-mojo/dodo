# App API probes

Throwaway spikes on Mojo 1.2.0 for the planned app API (`docs/design.md` section 4). Run one with `pixi run mojo -I . research/app-api-probes/<file>.mojo`. Files named `*_fail_*` are meant not to compile; the error quoted below is the first line the compiler prints (for comptime asserts, the message sits in a `note: constraint failed:` line below a generic `error: function instantiation failed`).

## P1 reflection.mojo

Builds a JSON Schema string for a struct with `String`, `Int`, `Float64`, `Bool`, `List[String]` and a nested struct. Field count, names and type names come from `reflect[T].field_count()`, `field_names()`, `field_types()`, and the whole schema is built at comptime: `comptime user_schema = schema_of[User]()` compiles, so String and List work in comptime evaluation. A field name must be bound to a `comptime` value before use (`comptime name = names[i]`), otherwise: `cannot materialize comptime value of type 'Array[StringSpan...' to runtime because it is not 'ImplicitlyCopyable'`. `Int` reflects as `SIMD[DType.int, 1]` and `Float64` as `SIMD[DType.float64, 1]`. `reflect[T].is_struct()` is true for these SIMD scalars, so test the name for `SIMD` before `is_struct()`, or the walk descends into MLIR internals (`get_type_name requires a concrete type`). An unsupported field is rejected at compile time with a readable message through `comptime assert False, "unsupported number type " + reflect[T].name()` (`reflection_fail_field.mojo`): `note: constraint failed: unsupported number type SIMD[DType.uint16, 1]`. The message names the type but not the field or the outer struct.

## P2 handlers.mojo, handlers_generic_state.mojo, handlers_fail_*.mojo

Overloads on function types work: `get(path, handler: def(Request) raises thin -> Response)` and `get(path, handler: def(Request, Model) raises thin -> Response, var state: Model)` coexist. The spelling must include `thin`; a `comptime` alias for a function type works as a parameter type but not as a `List` element type (`'List' parameter 'T' has 'AnyType' type, but value has type 'AnyTrait[def(Request) raises -> Response]'`). A non-raising `def(Request) -> Response` is accepted where the raising type is expected. One generic entry point `get[F: ImplicitlyCopyable](path, handler: F)` works with `comptime if F == PlainFn` plus `rebind`, and rejects others with a custom `constraint failed: handler must be def(Request) raises -> Response`. The best option: `get[S: Movable & Deinitable](path, handler: def(Request, S) raises thin -> Response, var state: S)` deduces the state type from the handler and rejects a mismatched state (`handlers_fail_state_mismatch.mojo`): `invalid call to 'get': value passed to 'state' cannot be converted from 'Model' to 'Counter'`. A wrong arity gives only `no matching method in call to 'get'` plus the candidates. A function's own type is opaque (`reflect[F].name()` prints `std.builtin._stubs.__MLIRType[<unprintable>]`), but argument and return types are recoverable by pattern: `def pick[A: AnyType, R: AnyType](f: def(Request, A) raises thin -> R)` infers `A` and `R`. Argument names cannot be read. Heterogeneous storage: `List[Handler]` fails (`'List' parameter 'T' has 'AnyType' type, but value has type 'AnyTrait[Handler]'`), and closures that capture state cannot be stored: `the 'escaping' function effect is no longer supported`, then `Could not infer capture convention of the captured value model` without it (`handlers_fail_closure.mojo`). What works is the heap box plus monomorphised thunk that `dodo/http/router.mojo` already uses (`Pool[H]`, `def(Int, Request) raises thin -> Response`), so the App can register each signature as a thunk at the generic `get` call.

## P3 comptime_paths.mojo, comptime_paths_fail_*.mojo

`app.get["/hello/{name}"](hello)` works with `path: String` as a parameter. A plain `def parse_path(path: String) -> ParsedPath` (loops, `List[String]`, early returns) runs at comptime, and `comptime assert parsed.error.byte_length() == 0, parsed.error` turns its message into a build error. All of these fail the build with a clear message: `/hello/{name` (`unclosed { in route path`), `/hello/name}` (`} without { in route path`), `/hello/{}` (`empty param name {} in route path`), `/hello/{name}/{name}` (`duplicate param name in route path`), `hello/{name}` (`route path must start with /`). Handler argument names cannot be inspected, so the path names are checked against the field names of a params struct the handler takes (`def hello(req, params: HelloParams)`): `/hello/{nam}` gives `constraint failed: path param has no matching field in the handler params struct` and an extra `{id}` gives `path param count differs from handler params field count`. Note the real Router uses `:name` today, not `{name}`.

## P4 misc.mojo, misc_fail_decorator.mojo

(a) User decorators do not exist: `error: unsupported compiler decorator` for `@route("/hello")` and for bare `@route`. (b) Works: `def take_state[S: Movable & Deinitable](mut self, var state: S)` accepts a struct, a trait-conforming struct and a `String`. `Movable` alone fails with `'state' abandoned without being explicitly destroyed: unhandled explicitly destroyed type 'AnyType'`; add `Deinitable`. (c) Works: `comptime if conforms_to(T, Describe):` then `rebind[downcast[T, Describe]](value).describe()` (same pattern as `dodo/json/reflection.mojo`), with an `else` branch for types that do not conform.

## P5 hello_dodo.mojo

Router plus `HttpServer.bind(SocketAddr.localhost(port))`, `server.serve(router^)`, and `serialize_json(Greeting(...))` for the body. Built with `pixi run mojo build`, started on port 18765: `curl /hello/world` returns `200`, `Content-Type: application/json` and `{"message":"hi world"}`; an unknown path returns `404`. The server was then stopped. The header must be set by hand (`response.headers.set(...)`), because `ok(String)` has no JSON variant yet. Build prints deprecation warnings from `dodo/http/_offload_pool.mojo` (positional `__getitem__`), not from the probe.

## P6 p6_lib.mojo, p6_typed_handlers.mojo, p6_shared_state.mojo, p6_fail_*.mojo

Typed handlers with 0 to 5 arguments on a stand-in App, with stand-in `Request` and `Response`. Each argument is recognized by a marker trait (`PathParams`, `QueryParams`, `JsonBody`, `State`) and filled through reflection; a returned struct becomes 200 JSON. A bad value or missing field gives a 400 problem+json naming the field. State is boxed once and borrowed: a Movable-only state compiled, and 8 threads making 2000 requests each saw the same address, with 0 mismatches. All 8 failing cases stop the build with our own message naming the route, under a generic `function instantiation failed` line.

## P7 p7_middleware.mojo

Two ways to attach middleware, on the real `Handler`, `Request` and `Response`. Form A wraps the whole app in generic wrappers, including the stock `RequestId`; stock middleware needs `Copyable`, so the app goes behind an `ArcPointer` handle. Form B is a boxed chain behind `app.use(m)`. Three pass-through layers cost about the same in both forms, 110 to 135 ns per request against 113 to 123 ns for the bare app, so the difference is within noise (macOS, three runs).
